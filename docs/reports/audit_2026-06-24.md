## 🔴 Critical Issues (Phải sửa ngay)

### 1. 🐌 N+1 Loop trong `upsertFromRemoteBatch` - Database chậm khi sync nhiều tin

**📍 File:** [ReadNewsDao.kt](file:///c:/Users/Administrator/Desktop/code/RSS-Reader-main/app/src/main/java/com/skul9x/rssreader/data/local/ReadNewsDao.kt#L107-L117)

**Triệu chứng:**  
Hàm `upsertFromRemoteBatch()` được đánh dấu `@Transaction` nhưng bên trong lại dùng vòng lặp `forEach` gọi từng query `upsertFromRemoteIfNotPending()` riêng lẻ.

```kotlin
@Transaction
suspend fun upsertFromRemoteBatch(items: List<ReadNewsItem>) {
    items.forEach { item ->  // ⚠️ N queries thay vì 1!
        upsertFromRemoteIfNotPending(...)
    }
}
```

**Hậu quả:**  
Nếu sync 500 tin đã đọc từ Firebase, hệ thống sẽ chạy **500 câu SQL** thay vì gom thành 1 batch. Trên thiết bị cũ hoặc Android Box, việc này có thể mất **3-5 giây** thay vì <100ms. `@Transaction` chỉ đảm bảo atomicity, KHÔNG tối ưu số lượng query.

**Cách sửa:**  
Sử dụng `@Insert(onConflict = IGNORE)` kết hợp `@Query` UPDATE riêng, hoặc xây dựng raw SQL batch upsert dùng `@RawQuery` với `SupportSQLiteQuery`. Hoặc đơn giản hơn: chunk thành nhóm 50 items và dùng `insertAll` với logic kiểm tra PENDING ở tầng repository thay vì tầng DAO.

### 2. 🐌 N+1 Loop trong `updateTranslatedTitles` - Cập nhật dịch thuật chậm

**📍 File:** [RssRepository.kt](file:///c:/Users/Administrator/Desktop/code/RSS-Reader-main/app/src/main/java/com/skul9x/rssreader/data/repository/RssRepository.kt#L368-L376)

**Triệu chứng:**  
```kotlin
suspend fun updateTranslatedTitles(translations: Map<String, String>) = withContext(Dispatchers.IO) {
    translations.forEach { (id, title) ->  // ⚠️ N queries!
        cachedNewsDao.updateTranslatedTitle(id, title)
    }
}
```

**Hậu quả:**  
Mỗi lần refresh 5 tin (thường có 3-4 tin cần dịch), hàm này chạy 3-4 câu UPDATE riêng lẻ. Tuy với số lượng nhỏ thì không quá nghiêm trọng, nhưng khi batch translation xử lý 15+ tiêu đề (chunk size), sẽ có **15 lần write database** riêng biệt.

**Cách sửa:**  
Gom vào `@Transaction` hoặc dùng `CASE WHEN` SQL để update nhiều row cùng lúc:
```kotlin
@Transaction
suspend fun updateTranslatedTitlesBatch(translations: Map<String, String>) {
    translations.forEach { (id, title) ->
        updateTranslatedTitle(id, title)
    }
}
```
Ít nhất wrap bằng `@Transaction` để Room gom tất cả thành 1 database transaction.

### 3. 🧱 `RssParser.fetchFeed()` dùng `execute()` đồng bộ - Block IO thread

**📍 File:** [RssParser.kt](file:///c:/Users/Administrator/Desktop/code/RSS-Reader-main/app/src/main/java/com/skul9x/rssreader/data/network/RssParser.kt#L40-L52)

**Triệu chứng:**  
```kotlin
val response = client.newCall(request).execute()  // ⚠️ Blocking call!
```

**Hậu quả:**  
Mặc dù hàm `fetchFeed()` là `suspend`, nó lại dùng `execute()` (blocking) thay vì `enqueue()` (async). Khi gọi từ `refreshAndGetRandomNews()` với `async { ... }`, mỗi feed sẽ chiếm 1 thread từ Dispatchers.IO pool. Với 9 default feeds, điều này giữ **9 threads** cùng lúc. Không gây crash nhưng:
- Không hỗ trợ cancellation (coroutine bị cancel nhưng HTTP request vẫn tiếp tục)
- Tốn thread pool resources khi có nhiều feeds

**Cách sửa:**  
Chuyển sang `suspendCancellableCoroutine` + `enqueue()` giống như đã làm trong `HtmlFetcher.kt` và `GeminiApiClient.kt`. Codebase đã có pattern chuẩn, chỉ cần apply pattern tương tự.

### 4. ⚠️ `getAllReadIds()` kéo toàn bộ lịch sử lên RAM

**📍 File:** [ReadNewsDao.kt](file:///c:/Users/Administrator/Desktop/code/RSS-Reader-main/app/src/main/java/com/skul9x/rssreader/data/local/ReadNewsDao.kt#L44-L45) → [RssRepository.kt](file:///c:/Users/Administrator/Desktop/code/RSS-Reader-main/app/src/main/java/com/skul9x/rssreader/data/repository/RssRepository.kt#L77-L79)

**Triệu chứng:**  
`getAllReadIds()` trả về toàn bộ history. Tuy hàm `filterOutReadNews()` đã được tối ưu dùng `getAlreadyReadIds(chunk)` thay vì `getAllReadIds()`, nhưng hàm `getAllReadIds()` vẫn có thể bị gọi từ chỗ khác (ví dụ: `LocalSyncRepository.getAllReadIds()`).

**Hậu quả:**  
Sau 30 ngày sử dụng (retention 30 days), bảng `read_news` có thể chứa hàng chục ngàn records. `getAllReadIds()` sẽ load tất cả vào RAM, gây memory pressure trên thiết bị yếu.

**Cách sửa:**  
Thêm `LIMIT` hoặc filter theo khoảng thời gian. Hoặc audit xem `getAllReadIds()` còn được gọi ở đâu - nếu không cần thiết thì đánh `@Deprecated`.

### 6. ⚠️ `rememberInfiniteTransition` chạy liên tục trong `NewsCard`

**📍 File:** [NewsCard.kt](file:///c:/Users/Administrator/Desktop/code/RSS-Reader-main/app/src/main/java/com/skul9x/rssreader/ui/components/NewsCard.kt#L54-L63)

**Triệu chứng:**  
`rememberInfiniteTransition` tạo animation pulse chạy liên tục cho **mỗi card**, kể cả card không được chọn. Với 5 cards hiển thị, có 5 infinite transitions chạy đồng thời.

**Hậu quả:**  
Mỗi frame (16ms), Compose phải recalculate animation value cho cả 5 cards, dù chỉ card đang playing mới cần hiệu ứng pulse. Gây thêm CPU/GPU overhead trên Android Box.

**Cách sửa:**  
Chỉ tạo `infiniteTransition` khi `isPlaying == true`:
```kotlin
val pulseAlpha = if (isPlaying) {
    val transition = rememberInfiniteTransition(...)
    transition.animateFloat(...).value
} else {
    1.0f
}
```

### 7. ⚠️ Không có connection pool configuration tối ưu

**📍 File:** [NetworkClient.kt](file:///c:/Users/Administrator/Desktop/code/RSS-Reader-main/app/src/main/java/com/skul9x/rssreader/data/network/NetworkClient.kt)

**Triệu chứng:**  
OkHttp dùng default connection pool (5 idle connections, 5 minutes keepalive). App kết nối tới nhiều hosts khác nhau (9+ RSS feeds + Gemini API + Firebase).

**Cách sửa:**  
Cân nhắc tăng connection pool hoặc giảm idle timeout:
```kotlin
.connectionPool(ConnectionPool(10, 2, TimeUnit.MINUTES))
```

### 8. ⚠️ Thiếu `@Index` trên cột `readAt` trong `ReadNewsItem`

**📍 File:** [ReadNewsItem.kt](file:///c:/Users/Administrator/Desktop/code/RSS-Reader-main/app/src/main/java/com/skul9x/rssreader/data/model/ReadNewsItem.kt)

**Triệu chứng:**  
Nhiều query filter theo `readAt` (ví dụ `getTodayReadIds(todayStart)`, `deleteOlderThan(timestamp)`), nhưng cột `readAt` không được index.

**Hậu quả:**  
SQLite phải full table scan cho mỗi query filter theo thời gian. Khi bảng lớn (hàng chục ngàn records), sẽ chậm dần.

**Cách sửa:**  
Thêm index:
```kotlin
@Entity(
    tableName = "read_news",
    indices = [Index(value = ["readAt"])]
)
```
